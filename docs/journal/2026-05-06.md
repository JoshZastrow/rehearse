# 2026-05-06

Today we worked on making the assistant audibly switch roles as the call
moves through intake, practice, and feedback.

We started by closing two reliability gaps: streaming audio.wav to disk
during the call, and a finalize sweeper for sessions stuck when Twilio
drops the status webhook.

Then we reviewed a live call from earlier. The phase manifest had
transitioned all the way through, but the assistant stayed in coach mode
the whole time. We realized Hume was calling Anthropic directly with one
static prompt. Our phase-aware `/chat/completions` webhook was wired but
never reached.

We routed the personas through `CUSTOM_LANGUAGE_MODEL` so every turn
comes through our service. We added a `feedback_coach` role and a
`PersonaSwapCoordinator` that speaks a bridge utterance on each phase
change.

We also tightened the phase cue detector. Consent answers were counting
as intake turns, and the bare word "feedback" was tripping transitions
early. We gated the counter on consent, made the cues phrasal, and added
a minimum dwell time per phase.

Syncing the new personas taught us four Hume constraints we didn't know
about — the CLM URL has to end in `/chat/completions`, prompt is
rejected, builtin tools are rejected, and the voice name gets
canonicalized to an id on POST. We patched each one.

The next live call hung up cleanly the moment audio arrived. Anthropic
was returning 401. The `.env` key looked right, but a stale export in
`~/.zshrc` was shadowing it. We added startup validation so a bad key
fails at boot, an in-call fallback line so a provider blip doesn't drop
the session, and made `.env` authoritative via
`load_dotenv(override=True)`.

Later we shifted to the eval side. The audio judges and naturalness
scorer had been shipped, but nothing connected them to real recorded
calls. We wanted to score yesterday's conversation.

The gap was the bundle shape. Production sessions write a single mixed
`audio.wav`. The judges expect per-turn WAVs under `audio/{user,coach}/`
plus a `timing.jsonl`. So we built a `ProductionReplayEnvironment` that
reads the bundle, slices `audio.wav` by transcript `ts_start`/`ts_end`
into per-turn-per-role files, synthesizes `timing.jsonl` from the same
intervals, and drops the result into `run_dir` as if it were any other
rollout. We paired it with `ProductionSessionsDataset` and a new
`production-voice-replay` eval that pipes through the existing audio
scorers unchanged.

While slicing we realized the coach turns all had
`ts_start == ts_end`. Hume's `assistant_message` event arrives with
text but no duration; the audio streams afterward. We were stamping
`ts_end = ts_start = now` on arrival. We added handling for the
`assistant_end` event, buffered the transcript frame until that fires,
and took `ts_end` from the elapsed clock at flush time. Coach turn
durations are now real.

We ran the dogfood eval live and hit 429 RESOURCE_EXHAUSTED on Gemini
2.5 Pro. We switched the default judge model to Gemini 2.5 Flash —
same audio capability, roughly an order of magnitude cheaper — and
made it env-overridable. We also confirmed Gemma is text+image only,
so it can't replace the audio judges.

Before writing the calibration code we wrote the implementation spec
for it. The roadmap convention is one spec per mini-spec before code
lands, and Mini-spec 3 is large enough — voice rating UI, parser,
harness, golden-set sampler — that skipping the design pass would
have been a rush. The draft sits at `acknowledged` until we lock the
three open questions inside it.

We also expanded `voice-judges-smoke` from one fixture sample to five
covering the valence × arousal grid. Without varied affect, the audio
judges have no signal to differentiate, and naturalness sub-metrics
never exercise their bands.

The result is that real calls are scoreable end-to-end on three
dimensions today, even if those scores aren't yet calibrated against
human ratings. That last gap is what the calibration spec is for.
