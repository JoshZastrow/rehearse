# 2026-05-12

Today we designed and built the agent architecture that lets Rehearse remember
callers across sessions.

We started by asking a question: why does the coach treat every call like the
first one? The answer was that the CLM webhook was one function doing four
jobs — format conversion, prompt assembly, memory (which didn't exist), and the
API call. Adding cross-session recall meant untangling all of that first.

We studied two references before writing a line of code. Hermes Agent uses a
`MemoryProvider` ABC with a `prefetch(query)` hook that runs before the LLM
call and a `sync_turn()` that runs after. Claude Agent SDK structures agents as
subagents with their own prompts, tool sets, and lifecycle hooks. Both pointed
to the same shape: a pipeline of distinct layers, each with one job.

We also looked at how Honcho actually works. Our existing `HonchoCallerMemory`
was writing caller data to peer metadata — treating it like a key-value store.
But Honcho's real memory model is sessions, messages, a background Deriver that
extracts observations, and a Dialectic that answers natural-language queries
over those observations. `peer.chat("What has this caller worked on?")` is what
we should be calling, not `get_metadata()["intakes"]`. We fixed the underlying
async bug too — `honcho.peer()` is a sync HTTP call that was blocking the event
loop on every consent check.

We designed five layers: `LLMTransport` for format conversion and streaming,
`MemoryManager` wrapping a `CallerMemoryProvider`, `RehearseAgent` with
`recall()` and `system_prompt()` and `after_turn()`, `AgentRegistry` mapping
names to instances, and `AgentRouter` that picks the right agent from the
session phase. `CLMResponder` orchestrates them in order — route, recall,
prompt, stream, after-turn — and knows nothing about Anthropic or Honcho.

We built each layer test-first. Each cycle: write a failing test, implement,
pass, commit. Seven commits landed on the feature branch by the end of the
session.

As we built the agents, we added `store_session()` to `telephony.py` so the
call transcript gets written to Honcho at the end of every call. Without that,
the Deriver has nothing to process, and `prefetch()` would always return empty.

The intake coach now asks: "What topics has this caller practiced before?" The
feedback coach asks: "What growth has this caller shown? What feedback landed
well?" Both queries go to the Honcho Dialectic, which searches stored
observations and returns a synthesized answer. That answer shows up in the
system prompt before the LLM speaks.

We also deleted `AnthropicCLMResponder` and `_system_prompt_for_role` at the
end of the session. The spec said to do it in a follow-up PR but the cleanup
was straightforward. `_message_content` and `_message_role` moved into
`AnthropicTransport`, where they belong.

What this lets us do next: add a specialized negotiation character by writing
one class and one routing rule. The registry and router already support it. The
first two calls from a returning caller won't show much — Honcho needs a
session before it has signal — but by the third call the recall context should
start to feel personal.
