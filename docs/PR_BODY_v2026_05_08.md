## What changes from a user's perspective

Run an eval and watch scores land live in a second terminal:

```bash
# Terminal 1
make eval-voice-rollout

# Terminal 2 (any time during the run)
rehearse-eval watch --run-id <run_id>
```

The `watch` command renders a `rich` table that updates as each scorer publishes. The runner appends every `RubricScore` to `<run_dir>/scores.jsonl` immediately; `watch` tails the file. Decoupled — runner writes, watcher reads.

Audio judges and naturalness scorers stop degrading. `runtime-sandbox` rollouts now produce a complete artifact bundle including `audio/{user,coach}/turn_<N>.wav` and `timing.jsonl`.

## Architecture

### Phase B — audio + streaming (default tier)

- **Post-hoc TTS in `runtime-sandbox`.** After the runtime/customer gather, each transcript turn is synthesized to a per-turn WAV via the configured `TTSProvider` (Hume Octave by default). `timing.jsonl` is derived from real WAV durations. `HUME_API_KEY` unset → silent WAVs sized by word count, `audio_stub=true` flag in `provenance.json`.
- **Audio helpers extracted.** `rehearse/eval/environments/_audio.py` is the single source of truth for `read_transcript`, `synthesize_turns`, `silent_audio`, `silent_wav`, `timing_from_frames`. `live_rollout_audio.py` and `runtime_sandbox.py` both consume it.
- **Score streaming.** New `rehearse/eval/score_stream.py:ScoreStreamWriter` is an append-only JSONL writer. Each `RubricScore` becomes one line at the moment a scorer returns it; line-buffered I/O so a tailing reader sees scores within ms.
- **Composite scorer publishes incrementally.** `CompositeScorer.score()` accepts an optional `publish` callback. Children stream as they finish; the aggregate streams last. `supports_publish()` is the runtime detection used by the runner.
- **Provenance JSON per rollout.** `provenance.json` documents the eval substitutions: which `CoachVoiceAdapter`, which `Channel`, which TTS provider, which API keys were available (boolean only).

### Phase C — mirror enforcement

- **`.github/workflows/schema-diff.yml`** triggers on PRs touching artifact-contract files (`runtime.py`, `intake.py`, `personas.py`, `types.py`, `phases.py`, `frames.py`, `runtime_sandbox.py`, `telephony.py`) and on push to `main`.
- Boots `RuntimeHost` via `runtime-sandbox` and via the serving path. Prints the JSON schemas of `Session`, `IntakeRecord`, `CounterpartyPersona`. Fails on a fixture mismatch between paths.

### Phase E — drop telecom and test-automation jargon

| Old name | New name | Why |
|---|---|---|
| `InMemoryDuplexTransport` | `InMemoryTwoWayChannel` | "duplex" is telecom; we're an AI product |
| `RuntimeDuplexEndpoint` | `TwoWayChannel` | same |
| `RuntimeTransport` (alias) | `Channel` | grounded in the product domain |
| `LLMCustomerDriver` | `SyntheticCaller` | "driver" is test-automation jargon |
| `CustomerDriver` (Protocol) | `Caller` | same |
| `CustomerDriverResult` | `CallerResult` | same |
| `TwilioBridgeTransport` | `TwilioPhoneBridge` | drop "transport"; "bridge" is grounded |

Old names re-exported with `DeprecationWarning` via PEP 562 module-level `__getattr__`. Removed in the next eval-system PR.

## Known gap surfaced during testing

A pre-existing race in `runtime.py` `_run_loop`: bus subscribers (transcript writer, intake processor, etc.) register their queues *inside* their `async for` loops, but each task starts with an `await _register_artifact(...)` that goes through `asyncio.to_thread()`. The first user `TranscriptDelta` can be published before subscribers register, dropping that frame.

The new audio test exposes this: a customer that sends a single user turn followed immediately by `customer_done` produces a transcript with **only the coach turn** (not the user's). I worked around it in the test with a 100ms pre-send sleep and noted the race in the test comment.

This is not introduced by this PR but should be fixed before mirror-full lands. Recommended fix: in `RuntimeHost.run`, replace the single `await asyncio.sleep(0)` with an explicit "all subscribers ready" handshake.
